# KoupreyPlus design-system guidance

Discover and preserve the existing Tailwind theme, components, spacing,
typography, icons, form controls, and page shells. Do not impose a new visual
system from this reference.

## Municipal-service UI priorities

- Use clear Thai-first labels and actionable validation messages.
- Make citizen tasks calm, guided, and usable on mobile.
- Make staff dashboards dense enough for work but keep hierarchy obvious.
- Distinguish draft, submitted, in-progress, completed, rejected, and error
  states with text and icons as well as color.
- Explain AI assistance and keep generated text editable before submission.
- Show upload limits, accepted formats, progress, failure, and removal clearly.
- Provide loading, empty, offline/provider failure, denied, and success states.
- Use semantic structure, visible keyboard focus, sufficient contrast, and
  large touch targets.

## Form behavior

- Preserve input after recoverable failure.
- Prevent duplicate submissions.
- Put field errors beside fields and a summary at the top for long forms.
- Confirm irreversible or sensitive staff actions.
- Never reveal another citizen's record through autocomplete, validation, or
  error text.
